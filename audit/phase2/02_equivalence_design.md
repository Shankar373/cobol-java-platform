# Phase 2: Generic Equivalence Hardening Design

This document details the hardening design of the comparison validator:

## 1. Comparison Verification Design Matrix
- **Missing expected files**: A file present in the baseline output directory but missing in Java execution must raise an explicit `baseline-only` failure.
- **Unexpected files**: A file generated by Java but not present in the baseline must raise a `java-only` failure.
- **Exit Code Parity**: If the baseline exit code and Java exit code mismatch, the validator must report a FAIL.
- **Expected Empty Output**: If a program does not expect output files (verified by the configuration `"compare.expect_no_output": true`), empty folders are validated as PASS.
- **Unexpected Empty Output**: If a program does not declare empty outputs, and both baseline and execute results are empty, it must fail.
- **Timestamps & Generated IDs**: The comparison contract will accept regex ignore patterns to normalize date, time, and transaction ID values before comparing contents.
