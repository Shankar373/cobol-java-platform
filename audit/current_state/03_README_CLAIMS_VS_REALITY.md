# 03. README Claims vs Reality

This document matches key marketing claims in the project's `README.md` against actual implementation reality.

---

## 1. Summary Matrix

| Marketing Claim | Status | Discrepancy / Reality |
| :--- | :---: | :--- |
| **Repository-agnostic behavior** | `PARTIALLY VERIFIED` | While Phase 3.1 - 3.5 introduces generic, model-driven analysis (Lexer, Parser, CFG, DataFlow, Dependencies), the legacy transpiler pipeline has several hardcoded references to specific structures of the target benchmarks (e.g. SQLite tables mapping in `logical_indexed_compare`). |
| **COBOL Discovery** | `VERIFIED` | Discovers `.cob`/`.cbl` sources inside `cobol_migrate.py`. |
| **Copybook Discovery** | `VERIFIED` | Walks repository to discover `.cpy` files. |
| **CALL Graph** | `VERIFIED` | Resolves calls static and dynamic analysis. |
| **Transpilation** | `VERIFIED` | Invokes the `opensourcecobol4j:2.0.0` Docker container to perform translation. |
| **OpenSource COBOL 4J / libcobj dependency** | `VERIFIED` | The transpilation output compiles and executes only when `libcobj.jar` is present in the classpath. |
| **Physical Comparison** | `VERIFIED` | Checks byte/hash equality of sequential output files. |
| **Logical Comparison** | `VERIFIED` | SQLite comparisons are used to parse COBOL binary database layouts vs baseline binary dat formats. |
| **Spring Boot / Batch / REST API / JPA** | `PARTIALLY VERIFIED` | The codebase contains template configurations and scaffolding for Spring Boot container projects (`target/modernized`), but the business execution remains emulation code rather than idiomatic decoupled Java. |
| **Docker execution** | `VERIFIED` | Packages modernized apps and executions via Docker runner. |
| **Native Java capability** | `FALSE` | The emulated Java classes generated by the COBOL 4J transpiler rely entirely on `libcobj.jar` emulation bindings (meaning it is emulated Java, not native Java). |
