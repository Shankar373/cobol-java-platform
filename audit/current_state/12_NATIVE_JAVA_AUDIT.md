# 12. Native Java Audit

This document presents the detailed architectural and dependency audit of the generated Java outputs.

---

## 1. Dependency Analysis

The transpiled Java classes generated by the COBOL 4J compiler during the pipeline run have a **hard dependency** on `libcobj.jar`.

- **Transpiler Classes**:
  - `jp.osscons.opensourcecobol4j.libcobj.CobolControl`
  - `jp.osscons.opensourcecobol4j.libcobj.ui.CobolAccept`
  - `jp.osscons.opensourcecobol4j.libcobj.data.CobolData`
- **Native vs Emulated Java**:
  - The generated code is **emulated Java**. It wraps variables in COBOL-like wrappers and runs execution blocks inside paragraph loop emulation structures.
  - It **cannot compile or run** without `libcobj.jar` on the classpath.

---

## 2. Spring Boot "Native" Layer Analysis

- **Runtime Independence Check**: The generated Spring Boot project (`target/modernized`) contains a unit test `RuntimeIndependenceTest` which verifies that `libcobj` classes are not loaded on the Spring Boot classpath.
- **How Independence is Achieved**: The Spring Boot project does **not** include the transpiled emulation classes. Instead, it runs hand-coded/templated Spring Batch jobs and services (`BusinessProcessingService.java`) that contain hardcoded templates matching either the BankCore or Claim PAS schema, running on standard JDBC and JPA.
