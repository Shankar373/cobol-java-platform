# 06. Native Java Acceptance Gate Definition

This document outlines the strict quality and architectural criteria required for a modernized Java application to be verified as genuinely "Native Java".

---

## 1. Acceptance Criteria

To pass the Native Java Acceptance Gate, a modernized COBOL-to-Java translation must satisfy the following four conditions:

### A. Zero Classpath Dependencies on COBOL Emulation
The generated Java source code must contain **zero imports** from the following packages:
- `jp.osscons.*`
- `libcobj.*`
- Any other COBOL emulation wrapper library.

### B. Clean Maven / Gradle Compilation
The generated Maven project must compile successfully (`mvn clean compile` returns exit code `0`) with **zero** references to `libcobj.jar` in its `pom.xml` dependencies list.

### C. Execution Independent of COBOL Runtime Libraries
The application must execute its batch pipeline or services using standard Java platform features (`BigDecimal`, primitive arrays, standard collections) without loading any helper classes from `libcobj.jar`.

### D. Business Parity Validation Success
The output files and databases generated by the native application run must match the original legacy baseline outputs under the existing equivalence contract.
